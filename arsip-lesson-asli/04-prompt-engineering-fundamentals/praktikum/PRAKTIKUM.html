05

Isi TODO di src/main.py

Bagian inti praktikum — 4 fungsi menunggumu. Kerjakan berurutan, satu TODO selesai → langsung tes di langkah 06.

TODO 1 — hitung_token(teks) tokenization

Kenapa? LLM membaca token, bukan huruf. Jumlah token menentukan biaya dan batas context window. Di sini kamu menghitungnya sendiri.
Petunjuk level 1 — arah umum
Baca docstring fungsinya: kamu hanya butuh 3 baris — ambil encoder, encode teks, kembalikan panjangnya.
Petunjuk level 2 — hampir jawaban
tiktoken.get_encoding("cl100k_base") mengembalikan objek yang punya method .encode(teks). Hasil encode adalah list — dan kamu sudah tahu cara menghitung panjang list 😉

TODO 2 — generate(prompt) /api/generate

Kenapa? Ini pintu utama ke model: kirim satu prompt, terima satu jawaban. Semua demo memakai fungsi ini.
Petunjuk level 1
Pakai requests.post(url, json={...}, timeout=TIMEOUT). URL, nama model, dan bentuk body JSON sudah tertulis di docstring.
Petunjuk level 2
Setelah r = requests.post(...), panggil r.raise_for_status(), lalu ambil r.json()["response"]. Jangan lupa "stream": False — tanpa ini server mengirim jawaban sepotong-sepotong.

TODO 3 — chat(messages) /api/chat

Kenapa? Aplikasi chat nyata mengirim daftar pesan dengan peran: system (aturan main), user (pertanyaan), assistant (jawaban sebelumnya). Di sinilah kekuatan system message terlihat.
Petunjuk level 1
Sangat mirip TODO 2 — bedanya endpoint /api/chat, kunci body "messages" (bukan "prompt").
Petunjuk level 2
Jawaban ada di r.json()["message"]["content"] — perhatikan: "message" (tunggal), beda dengan "messages" yang kamu kirim.

TODO 4 — buat_prompt_few_shot(contoh, input_baru) murni string

Kenapa? Few-shot = memberi contoh pola input => output, lalu membiarkan model meneruskan. Fungsi ini tidak menyentuh jaringan sama sekali — murni menyusun teks.
Petunjuk level 1
Loop tiap pasangan di contoh, buat baris f"{a} => {b}", gabungkan dengan "\n".join(...), lalu tambahkan baris terakhir f"{input_baru} =>" (tanpa jawaban!).
Cek manual sebelum lanjut
Hasil untuk [("apel","buah")] dan "mangga" harus persis:
apel => buah
mangga =>

Cek pemahaman: pesan dengan role apa yang mengatur "kepribadian" dan aturan main model?

b. Dari Demo 4: model menjawab pertanyaan fiktif dengan percaya diri. Mengapa ini berbahaya di aplikasi nyata (misal aplikasi kesehatan)? Sebutkan 1 cara menguranginya dari materi README.

Sudah menjawab? Bandingkan dengan poin diskusi
a. Prompt berformat menghasilkan struktur yang bisa langsung diproses program (JSON valid dengan kunci tetap), bukan paragraf bebas — inilah dasar membangun aplikasi di atas LLM.

b. Pengguna awam bisa memercayai informasi yang salah (misal dosis obat fiktif). Mitigasi dari materi: minta model menyertakan sitasi/alasan, beri model "jalan keluar" (fallback "saya tidak tahu"), atau suntik data terpercaya lewat konteks (RAG di lesson berikutnya).

Model menjawab meyakinkan tentang peristiwa yang tidak pernah ada. Kurikulum ini menyebutnya...

Eksplorasi: Bandingkan Antar Model

Kenapa? Materi bilang "model capabilities vary" dan "responses are stochastic" (jawaban bisa berbeda walau prompt sama persis). Jangan percaya begitu saja — buktikan sendiri!

Buka notebooks/eksplorasi.ipynb di Codespaces, pilih kernel Python dari .venv, jalankan sel dari atas ke bawah. Kamu akan:

  • Mengirim prompt yang sama ke beberapa model → bandingkan kecepatan & gaya jawaban.
  • Mengirim prompt yang sama 2× ke model yang sama → lihat jawabannya tidak identik (stokastik).

🧠 Checkpoint 2 — refleksi (juga diisi di sel terakhir notebook)

a. Model tercepat = model terbaik? Apa buktimu?

b. Dua percobaan dengan prompt identik menghasilkan jawaban berbeda. Mengapa penting diperhatikan saat membangun aplikasi?

Rangkuman, Tugas Lanjutan & Yang Dikumpulkan

Rangkuman — coba jelaskan tiap poin dengan kata-katamu sendiri

Prompt = antarmuka pemrograman
Kualitas prompt menentukan kualitas jawaban; merancangnya adalah keterampilan teknis, bukan tebak-tebakan.
Token & context window
Model membaca token, bukan teks; jumlah token memengaruhi biaya dan batas "ingatan" percakapan.
Instruksi spesifik & system message
Sebutkan audience, panjang, dan format; gunakan system message untuk mengunci gaya dan aturan main.
Few-shot
Contoh pola input→output sering lebih ampuh daripada instruksi panjang — model meniru pola.
Fabrication & stokastik
Selalu validasi output AI; jawaban bisa salah-tapi-meyakinkan dan tidak selalu sama antar percobaan.

🚀 Tugas lanjutan (opsional, buat yang penasaran)

  1. Cue technique: tambah demo sendiri di main.py — kirim teks tentang planet Jupiter (ada di README bagian Prompt Cues) diakhiri baris Top 3 Fakta yang Kita Pelajari: dan amati model "mengambil pancingan" itu.
  2. Prompt template pendidikan: rancang 1 template untuk kasus nyata di kampus (misal pembuat soal kuis dari materi kuliah). Uji minimal 2 iterasi, catat apa yang membaik.
  3. Lanjut ke Lesson 05 — Advanced Prompts (chain-of-thought dan teknik lanjutan).
